# 보고서 작성 워크플로

JRI 정책연구 보고서의 **최종 납품 포맷은 hwp**(한글 오피스)이지만, AI가 직접 편집하기 어려운 포맷이라 단계별로 다른 파일 형식을 사용한다.

## 단계별 포맷

| 단계 | 포맷 | 역할 |
|---|---|---|
| 초안 작성 | **md** | AI(클로드/Codex)가 자유롭게 편집. git으로 이력 관리. |
| 서식 파악 | **docx** | 한글 hwp 서식의 변환본. 표·번호·여백 등 구조 확인용. |
| 본문 편집 | **gdoc** | 협업·코멘트·실시간 이력 관리. 집필진/자문 의견 수렴. |
| 최종 납품 | **hwp** | JRI 표준 서식 `연구보고서_서식.hwpx` 사용. 한글에서 수동 마무리. |

표준 서식 자산은 `90.최종보고서/지침/`에 둔다. fileId 인벤토리는 `examples/지속가능지표/_출처.md`, `examples/서귀포/_출처.md` 참조.

## AI 도구별 역할과 제약

### 클로드 (Drive MCP 기준)

| 동작 | 가능 여부 | 도구 |
|---|---|---|
| gdoc/docx/pdf/hwp 읽기 | ✅ | `mcp__claude_ai_Google_Drive__read_file_content`, `download_file_content` |
| **새 gdoc 생성** (md/text → gdoc 자동 변환) | ✅ | `mcp__claude_ai_Google_Drive__create_file` |
| 기존 gdoc 복사 | ✅ | `mcp__claude_ai_Google_Drive__copy_file` |
| **기존 gdoc 본문 편집·append·insert** | ❌ | (해당 MCP 도구 없음) |
| hwp 직접 편집 | ❌ | — |

### Codex

기존 gdoc의 in-place 편집(코멘트·이력·권한 유지하면서 본문 수정)에 사용. 클로드의 빈자리를 메우는 역할.

### 한글 오피스

hwp 최종 편집·서식 확정. 사람이 수동으로 처리.

## 실무 가이드

**클로드로 처리할 수 있는 경우**

- 보고서 본문 초안을 md로 작성·수정
- md 초안을 새 gdoc으로 업로드 (기존 문서 옆에 v2 형태로 만들고 사람이 머지)
- gdoc/docx/pdf 본문 읽기·요약·분석
- 데이터 추출, 표 생성, 인용 정리

**Codex로 넘겨야 하는 경우**

- 기존 gdoc의 특정 단락·문장만 교체
- 코멘트·공유 권한·이력을 유지하면서 본문 수정
- gdoc 내 표·서식 부분 편집

**사람이 직접 해야 하는 경우**

- gdoc → hwp 변환과 한글 서식 최종 적용
- hwp 최종본 발주처 제출
